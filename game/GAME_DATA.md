# 게임에 쓸 수 있는 것 — 매도가 계산기에서 뽑은 자료

경매 사이클 게임(물건 선택 → 임장 → 시세조사 → 입찰 → 낙찰 → 명도 → 매도)을
만드는 쪽이 **이 파일 하나만 읽으면** 되게 정리했다. 계산기 코드를 볼 필요가 없다.

⚠️ **이 파일의 수치는 대부분 "경험적 참고값"이다.** 통계로 검증한 것과 아닌 것을
아래에서 칸을 갈라 표시했다 — 게임 밸런스로 쓰는 건 괜찮지만, 화면에 "확정된
수치"처럼 적으면 안 된다.

⚠️ **화면 문구에 출처(강의·강사명)를 드러내지 않는다.** 계산기가 지켜온 규칙이고,
게임도 같은 사람이 만드는 것이라 톤이 갈리면 안 된다. "현장에서는 보통…"처럼
본인 조언 투로 쓴다.

---

## 1. 게임 한 사이클 ↔ 쓸 수 있는 자료

| 게임 장면 | 쓸 자료 | 이 파일 어디 |
|---|---|---|
| 물건 카드 고르기 | 지역별 시장 분위기·매수층 | §6 지역 데이터 |
| 부동산 사장 대사 | 비교거래 목록 | 시나리오 JSON `comparables` |
| **임장** | 체크리스트 7개 | §3 임장 |
| 입지 확인 | 역·학교·편의시설 10종 + 판정 기준 | §4 입지 |
| 권리·서류 | 정비구역 4단계 | §5 정비구역 |
| 시세조사 | 예측구간·경고등 | 시나리오 JSON `prediction`·`warnings` |
| 입찰 | 레버리지·취득세·수익률 | §7 돈 계산 |
| **명도** | 기간·대행비 | §7 |
| **매도** | 상태별 3단계 + 호가 5단계 | §2 매도 |
| 결과 평가 | 환금성 9항목 점수 | §8 채점 |

## 2. 매도 — 게임의 결승선

### 2-1. ⭐ 명도 결과 → 매도가 (두 파트를 잇는 고리)

```js
const CONDITION_MULTIPLIER = { "노후": 0.90, "기본": 1.00, "올수리": 1.08 };
const CONDITION_LABELS = {
  "노후":   "노후 (수리 필요)",
  "기본":   "기본 (깨끗한 상태, 별도 수리 불필요)",
  "올수리": "올수리 (전체 리모델링 완료)",
};
const CONDITION_STEP_LABELS = {          // "지금 상태에서 더 손보면" 쪽 문구
  "기본":   "기본 정리 후 (청소·도배·장판 등)",
  "올수리": "올수리 후 (전체 리모델링)",
};
```

**게임 설계 제안**: 명도를 험하게 끝내면 `노후`, 원만하면 `기본`, 이사비를 넉넉히
주고 협의하면 `올수리`에 가깝게 — **협상 등급이 곧 매도가 배율**이 된다.
0.90 ↔ 1.08은 **18% 차이**라 체감이 확실하다.

⚠️ 실무에서는 **보통 "기본 정리"까지만** 하고 판다(청소·도배·장판). 올수리는 드문
선택지라 게임에서도 "그렇게까지 하면" 정도로 두는 게 현실적이다.

⚠️ 검증된 배율이 **아니다** — 국토부 실거래에는 수리상태 필드 자체가 없어서
데이터로 확인할 방법이 없다.

### 2-2. 호가 5단계 — 플레이어의 가격 전략 선택지

```js
const PRICE_TIER_LABELS = {
  urgent: "초급매가",   d30: "30일 목표가", d60: "60일 목표가",
  normal: "일반 매도가", test: "최고가 테스트",
};
```
분포상 위치는 각각 하위 10 / 30 / 50 / 70 / 92% 지점이다.

⚠️ **"30일/60일"은 실측 판매기간이 아니다.** 국토부 실거래에는 "언제 내놔서 언제
팔렸는지" 이력이 없다 — "싸게 내놓을수록 빨리 팔릴 것"이라는 상식을 옮긴 이름표다.
게임에서 실제 소요 일수를 굴리는 건 자유지만, **현실 근거가 있는 숫자는 아니다.**

### 2-3. 예상 소진 속도 라벨 (경쟁 매물 대비 위치로 판정)

| 보정 퍼센타일 | 라벨 |
|---|---|
| ~10% | 빠른 소진 가능성 매우 높음 |
| ~30% | 빠른 소진 가능성 높음 |
| ~60% | 정상 매도 구간 |
| ~85% | 다소 느릴 수 있음 |
| 그 위 | 장기화 가능성 큼 |

거래가 활발한 동네면 −10p, 뜸하면(월 1건 미만) +10p 보정한다.

### 2-4. 매도 압력 (경쟁매물 ÷ 월평균 거래) — 몇 개월치 물량인가

| 개월수 | 라벨 |
|---|---|
| 2개월 미만 | 낮음 — 값만 맞으면 비교적 빨리 소화 |
| 2~4 | 보통 — 가격이 매도 속도를 가르는 구간 |
| 4~8 | 다소 높음 — 빨리 팔려면 30일 목표가 쪽 |
| 8 이상 | 높음 |

## 3. 임장 — 체크리스트 7개 (그대로 게임 미니게임)

```js
const INSPECTION_CHECKLIST = [
  "채광 나쁨", "주차공간 부족", "누수 흔적 있음", "악취 심함",
  "소음 있음", "건물 관리상태 열악", "경사 심함",
];
```

- **전부 "나쁜 상태"를 서술하는 이름이다** — 중립 명사("채광")로 두면 좋아서
  체크하는 건지 나빠서인지 모른다. 실제로 그 지적을 받고 고친 이름이다.
- **엘리베이터는 일부러 뺐다** — 건축물대장으로 자동 확인되는 항목이라 임장에서
  또 체크하면 **한 요소로 두 번 감점**된다. 게임도 같은 함정을 피할 것.
- 판정: 문제 0개 + "문제 없음" 확인 → 👍 / 1개 → ➖ / **2개 이상 → ⚠️**
- ⚠️ **"아직 안 가봤다"와 "가봤는데 멀쩡하다"를 구분해야 한다.** 체크 0개만으로는
  구별이 안 돼서, 계산기는 "문제 없음" 체크를 따로 받는다. 게임에서도 임장을
  안 간 플레이어가 공짜로 점수를 받으면 안 된다.

**게임 설계 제안**: 임장을 가면 7개 중 **몇 개만** 보이게 하고(시간·집중력 자원),
안 본 항목은 매도 단계에서 드러나게 하면 "안 알아본 만큼 손해"가 성립한다.

## 4. 입지 — 10종 + 판정 기준

```js
const LOCATION_GROUPS = [
  ["🚇 교통", ["지하철역", "버스정류장"]],
  ["🏫 교육", ["초등학교", "중학교", "고등학교"]],
  ["🏪 생활", ["편의점", "대형마트", "공원"]],
  ["🏥 의료", ["병원", "약국"]],
  ["🌳 자연", ["산", "하천/강"]],        // 실험적 — 정확도 낮음
];
```

⚠️ **점수에 쓰는 건 둘뿐이다** — `지하철역`·`초등학교`. 나머지 여덟은 분위기용이다.
편의점이 200m냐 400m냐가 빌라 매도 속도를 가르지는 않는데 다 점수에 넣으면
**변별력이 흐려진다.**

| | 2점 | 1점 | 0점 |
|---|---|---|---|
| 지하철역 | 800m 이내 | 1,200m 이내 | 그 밖 |
| 초등학교 | 500m 이내 | 1,000m 이내 | 그 밖 |

합계 3~4점 👍 / 2점 ➖ / 0~1점 ⚠️.
(도보 10분 ≈ 800m, 초등 통학권 ≈ 500m라는 통상 기준을 옮긴 값이다.)

⚠️ **혐오시설(유흥가·모텔촌·공장)은 뺐다** — 매도에 제일 크게 영향을 주는 건
맞지만 검색으로는 정확히 못 잡는다. **게임은 오히려 이걸 넣기 좋다**(임장 이벤트로
직접 보여주면 된다). 현실 데이터가 없어서 못 넣은 것이지 중요하지 않아서가 아니다.

## 5. 정비구역 — 4단계 (게임의 대박/함정 카드)

```js
const REDEV_STAGES = {
  "":     "모름",
  "no":   "정비구역 아님",
  "early":"정비구역 — 초기 (추진위·조합설립)",
  "late": "정비구역 — 진행 (사업시행인가·관리처분)",
};
```

⭐ **게임 소재로 최고다.** 실측 사례 하나만 봐도 폭이 어마어마하다:

| 실제 사례 | 광명 1991년식 34㎡ |
|---|---|
| 실제 거래가 | **6.5억** |
| 동네 평균 기준 | 2.3억 |
| **배수** | **2.81배** |

정비구역 빌라는 **건물이 아니라 대지지분(입주권) 값**으로 팔린다. 그래서:
- 같은 동·같은 평형인데 **길 하나 건너면 프리미엄이 통째로 0**이 된다
- 단계가 올라갈수록(추진위 → 조합설립 → 사업시행인가 → 관리처분) 계단식으로 뛴다

**게임 설계 제안**: "권리분석/서류 조사"를 해야만 이 카드가 드러나게 한다.
안 하고 입찰하면 → 대박이거나 폭망. 그게 정확히 현실이다.

## 6. 지역 데이터 — 전국 맵을 만들 수 있다

| 파일 | 내용 | 게임 쓸모 |
|---|---|---|
| `data/lawd_codes.md` | 서울·경기 시군구 코드 (71행) | 지역 목록 |
| `data/buyer_age_by_region.csv` | **전국 시군구 274개** × 연령 6구간 × 2019~2025 | ⭐ **전국 맵**, 지역 성격 |
| `data/reb_villa_market_index.csv` | 시/도별 빌라 매매수급지수 월별 | 지역 난이도 |
| `data/reb_villa_market_index_seoul_zone.csv` | 서울 5개 권역(도심·동북·서북·서남·동남) | 서울 세분화 |

### 매수층 두께 = 지역 성격

30~40대 비중(실거주 주력 매수층)이 **서울 25개 구에서 41.8% ~ 66.1%로 갈린다.**
전국은 15.8% ~ 69.8%. **어느 지역을 골라도 비슷한 숫자가 나오는 지표가 아니라서
게임 난이도 축으로 바로 쓸 수 있다.**

| 예 | 30~40대 비중 |
|---|---|
| 서울 서대문구 | 64.1% (서울 평균 58.7%) |
| 경기 고양시 덕양구 | 47.6% (경기 평균 51.8%) |
| 전국 평균 | 50.1% |

### 시장 분위기 지수 (기준선 100)

100 초과 = 사려는 사람이 더 많음(매도자 유리) / 100 미만 = 매수자 유리.

| | 2025-11 | 2026-08 |
|---|---|---|
| **서울** | 104.6 | **111.5** ↗ |
| 경기 | 95.8 | 98.0 |

⚠️ **일회성 스냅샷이다** — 자동 갱신 안 됨. 게임에는 오히려 좋다(고정값이라 밸런스가
안 흔들린다).

⚠️ 연령 데이터는 **주택유형 구분이 없다**(아파트 포함 전체 주택). 빌라만 따로 뽑은
자료가 아니라는 점을 알고 써야 한다.
⚠️ **광주광역시·전라남도는 원본이 한 라벨로 묶어 놔서 못 가른다** — 그 두 지역은
게임 맵에서 빼거나 하나로 합쳐야 한다.

## 7. 돈 계산 — 입찰·명도·세금

⚠️ **여기 숫자는 전부 "사례 기준"이다.** 실제 수익률·금리를 보장하지 않고,
세법은 시점마다 바뀐다. 게임 밸런스용으로만 쓴다.

### 레버리지 (입찰 단계의 핵심 규칙)

```
현금 : 대출 = 3 : 7
낙찰가 = 투자금의 약 3 ~ 3.5배
예) 현금 5천 + 대출 1억 = 낙찰가 1.5억 → 매도가 1.8억
```

**투자금 구간별 타겟 물건** — 게임의 스테이지 구분으로 그대로 쓸 수 있다:

| 투자금 | 노리는 물건 |
|---|---|
| 5천만 ~ 1억 | 수도권 비규제 빌라 올현금 단타 / 지방 3억 이하 주거용 |
| 1억 ~ 2억 | 수도권 비규제 빌라 / 3~4억대 P2P 단타 |
| 2억 ~ 4억 | 낙찰가 12억 이하 대형 단타 |

### 대출 금리 (선택지마다 트레이드오프)

| 종류 | 금리 | 조건 |
|---|---|---|
| 주택담보 가계대출 | 약 4% | **전입의무** |
| 부동산매매 사업자 | 약 4.5% | 지방 |
| 전자상거래 사업자 | 약 4.5% | 리스크 |
| P2P | 약 12~18% | 단기 |
| 대부 | 약 15~18% | 단기 |
| 지인 차용 | 0~8% | — |

⭐ **게임 메커닉으로 훌륭하다** — 싼 돈에는 조건이 붙고, 급한 돈은 비싸다.

### 명도

- 인도명령 기준 **길어야 3~6개월**("1~2년"이 아니다)
- 쉬운 명도는 직접, 어려운 명도는 **대행 약 200만원**

### 취득세·비용

| | |
|---|---|
| 취득 부대비용 | **1.1%** (1주택/무주택 기준) — 다주택·규제지역이면 최대 13% |
| 매도 중개수수료 | 0.5% |
| **취득세 중과배제** | 수도권 공시가 **1억 이하** / 지방 **2억 이하** |

⭐ 중과배제 기준선이 **게임의 숨은 규칙**이 된다 — 1억을 살짝 넘기면 세금이 확
뛰므로, "딱 그 아래를 노리는" 전략이 성립한다. 실제 전략이기도 하다.

### 수익률 예시 (사례 기준, 보장 아님)

단기매도 주거용 연 50% / 2년 보유 비과세 연 40% / 현금흐름 오피스텔 연 30%.

> **수요가 적은 물건은 수익률이 높은 대신 환금성이 낮다.**
> ← 게임 전체를 관통하는 트레이드오프로 쓰면 좋다.

## 8. 채점 — 환금성 9항목 (게임 결과 화면)

중요한 순서대로다. **앞쪽 = 물건 자체 속성, 뒤쪽 = 시장 지표.**

| 순 | 항목 | 👍 | ➖ | ⚠️ |
|---|---|---|---|---|
| 1 | 가격 위치 | 상위 30% 이하 | 60% 이하 | 60% 초과 |
| 2 | 층·승강기 | 2~3층 / 승강기 있는 고층 | 1층, 승강기 없는 4층 | **반지하**, 승강기 없는 5층+ |
| 3 | 역세권·학세권 | 3~4점 | 2점 | 0~1점 |
| 4 | 임장 체크 | 문제 0개 | 1개 | 2개+ |
| 5 | 연식 | 15년 이내 | 30년 이내 | 30년 초과 |
| 6 | 거래량 | 월 3건+ | 월 1건+ | 월 1건 미만 |
| 7 | 경쟁 매물 | 낮음 | 보통 | 다소 높음·높음 |
| 8 | 시세 판단 근거 | — | — | — |
| 9 | 인근 아파트 대비 | 60% 이하 | 80% 이하 | 80% 초과 |

**점수 = 판정된 항목 평균** (👍 100 · ➖ 60 · ⚠️ 25).
75+ "환금성 좋은 편" / 50+ "보통" / 그 미만 "주의 — 팔기 어려울 수 있음".

⚠️ **"정보 없음"은 점수에서 빼야 한다** — 안 알아본 걸 감점하면 안 된다(대신
불확실성이 커지는 쪽으로 반영한다).

### 인근 아파트 대비 (9번) — 게임 지역 선택의 숨은 축

**비율 = 빌라 ㎡당가 ÷ 인근 아파트 ㎡당가. 낮을수록 좋다.**

| 비율 | 판정 |
|---|---|
| 60% 이하 | 👍 갭이 넉넉 — 아파트를 못 사서 내려오는 수요가 두껍다 |
| 60~80% | ➖ 보통 |
| 80% 초과 | ⚠️ 굳이 빌라를 고를 이유가 약해진다 |

⚠️ **단기보다 중·장기 신호다** — "지금 빨리 팔린다"가 아니라 "수요층이 두껍고
키 맞추기 상승 여력이 남았다"는 뜻이다.

### 반지하 — 게임에서 반드시 다르게 취급할 것

**반지하는 지상층의 절반 수준으로 시세가 형성되는 경우가 흔하다.** 계산기는 아예
비교 대상에서 양방향 제외한다. 한쪽만 걸어뒀다가 **반지하 물건 매도가가 두 배로
부푼 실제 사고**가 있었다(평균 오차 42.6%). 게임도 반지하를 별도 트랙으로 둘 것.

### 1층 — 약 7% 할인

백테스트로 확인된 실측 효과다(위층과 섞으면 1층은 과대평가, 위층은 과소평가).
**위 9항목 중 유일하게 통계로 검증된 보정치**라고 봐도 된다.

## 9. 멘토 대사 소재 — 그대로 써도 되는 문장들

```
"빌라는 아파트의 대체재예요. 인근 아파트보다 비싸지면 잘 안 팔립니다."
"싸게 사는 것보다, 실제로 팔릴 가격을 먼저 계산하세요."
"금액이 싸면 팔리긴 팔리는 빌라를 고르세요 — 팔기 어려운 요소부터 제거하고."
"빌라는 개별성이 강해서 실거래 한 건만 보고 가격을 정하면 안 됩니다."
"평당가를 맹신하지 마세요. 업거래가 섞여 있을 수 있어요."
"수익률이 높은 물건은 환금성이 떨어질 수 있어요 — 회전 가능성을 같이 보세요."
"하자 있는 물건이 아니라 '통제 가능한 하자'여야 합니다."
"한 번의 대박보다 반복 가능한 시스템이 목표예요."
"공급이 늘고 수요가 줄면 가격은 내려갑니다 — 경매도 경쟁자 수를 같이 보세요."
```

### 경쟁을 피하는 하자 6단계 — 물건 카드 분류축으로 쓸 수 있다

입지 / 물종 / 물건 / 법리 / 절차 / 시장.
"남들이 꺼리는 이유"가 곧 싸게 사는 이유라는 구조 — **게임 카드 태그로 그대로 쓴다.**

## 10. ⛔ 게임에 넣으면 안 되는 것

| | 왜 |
|---|---|
| **실시간 API 조회** | 실거래는 매달 갱신돼 **밸런스가 통째로 무너진다.** API 일일 한도도 실제로 넘긴 적이 있고, 첫 조회가 3~4초 + 서버 깨우기 수십 초다 |
| 네이버부동산 자동 수집 | 약관 위반 소지 + 이미 차단돼 있다. 붙여넣기 방식만 쓴다 |
| 진짜 단지명·주소 | 공개되는 페이지라 가명으로 바꾼다(`export_scenario.py`가 자동으로 한다) |
| 위 수치를 "확정"으로 표기 | 대부분 경험적 참고값이다 |

## 11. 가격은 어떻게 받나

`scripts/export_scenario.py`가 시나리오 JSON을 구워 준다. **게임은 그 파일만 읽으면
되고 파이썬도 API 키도 필요 없다.**

```
--js 를 주면 const SCENARIO_XXX = {...}; 형태로 나와 그대로 붙여넣을 수 있다
```

담기는 것: `subject` · `scenarios`(매도가 5값 + 경매용) · `prediction`(예측구간) ·
`tiers`(호가 5단계) · `warnings` · **`condition_ladder`**(명도↔매도 고리) ·
`comparables`(대사 소재) · `liquidity` · `truth`(정답, 플레이어에겐 안 보임) ·
`reveal`(어느 액션이 어느 키를 여는지).

**난이도 손잡이는 `--truth-pos`** — 정답을 예측구간 어디에 둘지(0.5 쉬움, 0.05·0.95
어려움). 구간 폭 자체는 물건이 정한다(소형·구축·모델 불일치면 자동으로 넓어진다).
즉 **"원래 감이 안 잡히는 물건"이 게임에서도 그대로 어렵다.**
